# Storage 预算与安全清理方案

本文件是审计方案，不代表本轮已经修改 Storage。

## 图片限制

- 普通日记：每人每天最多 1 篇，每篇最多 1 张。
- 原文件选择上限 10MB；浏览器本地处理最长边 ≤1600px，优先 WebP，质量 70%–78%。
- 目标 ≤500KB；压缩后 >800KB 拒绝。
- 不保留原图，不生成第二份副本，不用第三方压缩 API，不启用 Supabase 付费图片转换。
- 头像最长边 ≤512px，目标 ≤150KB；每位用户只保留当前头像。
- Mood、评论、正文评注、评注回复、Calendar 不上传图片。
- Memories 复用日记图片引用，不复制对象。

## 年度上限估算

- 理论最大：2 × 365 = 730 张日记图片/年。
- 按 500KB 目标：约 365MB/年。
- 按 800KB 硬上限：约 584MB/年。
- 两个头像按 150KB 计可忽略不计；实际增长取决于有图日记比例。

## 查看用量

- Supabase Dashboard → Storage 查看 bucket、对象数与用量。
- 按 bucket/prefix 汇总 `storage.objects`，区分日记图片与头像。
- 月度记录对象数、总字节、最大对象和新增速率。

## 识别与安全清理孤立文件

1. 导出业务表中全部当前图片路径。
2. 只读列出 Storage 对象清单。
3. 用 bucket+path 做差集；对象存在但无业务引用即为候选孤立文件。
4. 对新上传但事务未完成的对象设置安全等待期。
5. 先生成含路径、大小、创建时间、引用检查的报告并人工确认。
6. 先隔离或记录可恢复清单，不对未知前缀递归删除。
7. 再次检查引用后分批删除，保留日志与回滚窗口。
8. 头像上传成功且 profile 更新成功后，才删除旧格式对象。

## 费用风险

- 保留原图、多尺寸副本、Memories 重复图片。
- 频繁签名、重复下载和高出站流量。
- 视频、GIF、音频、附件或付费图片转换。

## 当前风险

- `avatars` bucket 是 public。
- 上传上限 2MB，未做浏览器压缩。
- 头像路径包含扩展名，格式变化可能遗留旧对象。
- 当前尚无日记图片 bucket。
- 按要求，本轮只报告，不改变 bucket 或删除对象。
